# 08 - Web API Specification

Base path `/api/v1`. The mobile endpoints are specified separately in `09-mobile-sync-contract.md`. The OpenAPI document is generated by FastAPI; this file is the design reference. Routes are tagged `web` or `mobile`.

## 1. Conventions
- JSON; `snake_case` fields; UTC timestamps (`...Z`); dates `YYYY-MM-DD`; ids are UUIDs (employees are also addressable by `tally_id` in filters).
- **Auth**: web login returns a 15-minute access token in the body (kept in memory) and a rotating refresh token in an httpOnly, Secure, SameSite=Strict cookie. Every endpoint enforces **role and reporting scope** server-side.
- **Pagination** (cursor): `?limit=50&cursor=<opaque>` -> `{ "items": [...], "next_cursor": "..." | null, "total_estimate": 1234 }`. Max limit 200.
- **Filtering and sorting**: explicit query parameters per endpoint, `sort=field` or `sort=-field`.
- **Optimistic locking**: updates send `version`; a mismatch returns `409 VERSION_CONFLICT`.
- **Idempotency**: create endpoints accept `Idempotency-Key`; replays return the original result.
- **Errors** (RFC 7807):
```json
{ "type": "about:blank", "title": "Validation failed", "status": 422, "code": "VALIDATION_ERROR",
  "detail": "...", "errors": [ { "field": "required_staff_count", "code": "MUST_BE_POSITIVE", "message": "..." } ] }
```
Common codes: `UNAUTHENTICATED` 401, `FORBIDDEN` 403, `OUT_OF_SCOPE` 403, `NOT_FOUND` 404, `VERSION_CONFLICT` 409, `REFERENCED_RECORD` 409 (cannot delete), `VALIDATION_ERROR` 422, `RATE_LIMITED` 429.
- **Warnings** on scheduling writes: response `200/201` includes `"warnings": [{ "code": "WEEKLY_OFF", "message": "..." }]`. Requests that proceed past warnings send `"acknowledge_warnings": ["WEEKLY_OFF"]`; unacknowledged warnings return `409 WARNINGS_REQUIRE_ACK` with the list.
- **Long operations** (import commit, report export, payroll run) return `202` with a job resource `{ "job_id", "status", "result_url" }`.
- **Audit**: every state-changing call writes an `audit_logs` entry; `X-Reason` header or `reason` body field is required where noted (reassignments, rejections, overrides).

## 2. Endpoint catalog
Roles: A = Admin, E = Engineer, S = Superintendent, V = Supervisor. "scope" = limited to reporting scope.

### Users and accounts
`GET /users`, `PATCH /users/{id}` (active/role), `POST /users/{id}/reset-password` (**Admin only**: sets the user back to the company default password and forces a change; applies to workers too).

### Groups, Zones, Accommodations
`GET/POST/PATCH /groups`, `/zones`, `/accommodations` (A write; A E S V read). `PUT /accommodations/{id}/boundary` (GeoJSON Polygon). Delete only if unreferenced.

## 3. Selected request/response examples
**Create scheduled work**
```http
POST /api/v1/scheduled-work
{ "employee_id": "uuid", "occurrence_id": "uuid", "work_date": "2026-11-03",
  "assigned_hours": 3.0, "sequence": 1, "acknowledge_warnings": [] }
```
`201`:
```json
{ "id": "uuid", "status": "ACTIVE", "sequence": 1, "version": 1,
  "warnings": [ { "code": "SGD_MISMATCH", "message": "Employee is a Gardener Helper; item requires Gardener Expert." } ] }
```
If a warning is not acknowledged: `409 WARNINGS_REQUIRE_ACK` with the same `warnings` list.

**Week view (shape)**
```json
{ "week_start": "2026-11-02",
  "worksites": [ { "worksite_id": "uuid", "job_number": "12A14301", "job_name": "...", "has_boundary": true,
    "items": [ { "job_item_id": "uuid", "sub_item_code": "A", "staff_grade_description": "Gardener - Hand Watering",
      "frequency_label": "6 per week", "required_staff_count": 3, "hours_per_occurrence_per_staff": 9.0,
      "days": [ { "date": "2026-11-02", "occurrence_id": "uuid", "required": 3, "assigned": 2,
                  "required_man_hours": 27.0, "assigned_man_hours": 18.0, "status": "UNDERSTAFFED", "flags": [] } ] } ] } ] }
```

**Attendance decision**
```http
POST /api/v1/attendance/{id}/decisions
{ "decision": "REJECTED", "comment": "Exit time not credible; please explain gap 10:05-11:40." }
```
Writes an `attendance_approvals` row for the current calculation version and sets review status to REJECTED.

**Import flow**: `POST /imports` (file) -> `GET /imports/{id}/preview` (new / updated with old-vs-new values / unchanged / clashes) -> fix and re-upload or `POST /imports/{id}/commit` -> poll the job -> `GET /imports/{id}/errors.xlsx`.

**Payroll preview**
```http
POST /api/v1/payroll/runs   { "period_start": "2026-10-01", "period_end": "2026-10-31", "country": "AE" }
```
`202` -> job; `GET /payroll/runs/{id}` returns status DRAFT with totals and `issues_count`; `POST .../approve` freezes it.

## 4. Implementation notes
- All list endpoints apply `scope_filter(user)` in the repository layer.
- Controllers stay thin (see `.agents/skills/add-endpoint`). Business rules come from `rules/`.
- Generate the TypeScript client for the dashboard from the OpenAPI file (`openapi-typescript`).
- Export the mobile contract with `tools/export_openapi.py --tag mobile > openapi-mobile.json` in CI.
