## Answers recorded (owner, 20 Nov)
- **Worksite supervisor scoping (DEC-57).** The rule is in handover section 0. Supervisor A's crew member working on supervisor B's worksite: B sees that worker read-only on B's worksite (attendance and live position, may comment). Approvals stay with A's chain (DEC-10). A sees the crew member only on Employees, Leave and A's own requests.
- **Deleting future salary rows vs golden rule 5.** A future row isn't referenced yet, so a hard delete is allowed only when `effective_from > site_today`, with a full-row audit snapshot. Later CREW_BREAK rows are recomputed; CREW_BREAK rows can't be deleted directly.
- **Revision grade suffix.** The client wants `G3C-2026` shown (meeting item 10), but the code stores the base code everywhere and builds the suffix for display from the revision's `suffix_label`.
- **Controlled dropdowns.** These are hard-coded lists, not managed ones; Batch 5.1 C replaces them. Grade dropdowns read the managed grade list, never revision lines.
- **Engineer access.** Engineers import and export employees and worksites (meeting item 1). Salary sheets and revision lines are Admin-only; Engineer exports leave out salary and budget columns.
