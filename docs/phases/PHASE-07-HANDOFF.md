## 1. Executive Summary

Phase 07 established the complete **Mobile Sync Contract** (`docs/09-mobile-sync-contract.md`), mobile authentication, single-device binding, sliding 30-day schedule synchronization, and the immutable raw location event ingestion pipeline (`POST /api/v1/mobile/events/batch`).

To facilitate end-to-end integration without depending on external mobile hardware, a standalone **Mobile Tester Proxy** (`tools/mobile-proxy/`) was built. It mirrors a worker's mobile smartphone, renders server-synced spatial boundaries, generates realistic movement events, and dispatches event batches directly to the backend.

During this phase, **102 raw location events** for worker `Mohan Lal (1017)` were simulated, dispatched, and verified in the database.

## 2. Key Tool: Mobile Tester Proxy (`tools/mobile-proxy/`)

### How to Run
- Standalone HTML/JS app running on `http://localhost:3000` (via `npx serve tools/mobile-proxy` or opened directly in a modern browser).
- Connects to backend API: `http://localhost:8000/api/v1`.

### Capabilities & Architecture
1. **Worker Authentication & Password Enrollment**:
   - Signs in with worker `tally_id` (e.g. `1017`) and password (`Welcome123!`).
   - Automatically handles forced first-login password updates.
   - Enforces device binding header checks (`DEV_SIM_1193_A`).
2. **Tabbed Mobile Viewport**:
   - **Today**: Current date, shift times, alarm status, and today's assigned worksite.
   - **GPS / Tracking**: Live coordinates, zone detection (`CAMP`, `WORKSITE`, `TRANSIT`), event buffer, and manual event buttons.
   - **Roster**: 30-day sliding schedule view with working days and rest days.
   - **Profile**: Worker identity, staff grade, weekly off day, and assigned supervisor.
   - **Sync**: Snapshot pull, delta changes pull (`?cursor=N`), and server cursor acknowledgment (`/sync/ack`).
3. **Interactive Leaflet Map & Spatial Sync**:
   - Renders **Living Accommodation** (Green polygon) and **Assigned Worksites** (Blue polygon + Geofence circle) synced strictly from PostGIS data.
   - **Auto-Fit Viewport**: Automatically computes the bounding box across accommodation and worksites so both areas are centered and visible.
   - **Dynamic Auto-Route Generation**: Computes a realistic route between the worker's synced camp and assigned worksite with arrival at `06:02`, midday stay, exit at `15:31`, and return to camp at `16:00`.
   - **Route Playback & Speed Scrubber**: 1x, 10x, 60x, 300x speeds with timeline slider and audio synthesizer for shift alarms.
   - **Ground Truth Analytics**: Displays actual worked minutes, transit time, and estimated confirmation pings based on the server's company settings.
4. **Boundary & Polygon Tools**:
   - **Custom Polygon Tracing**: Click on map to trace custom polygons, calculate surface area ($m^2$ and hectares), and copy GeoJSON or WKT.
   - **"🧹 Clear Map" Button**: Wipes all custom scratch layers and resets the canvas cleanly.
   - **Web Dashboard Integration**: The web dashboard's polygon editor (`web/src/features/map/PolygonEditor.tsx`) has a **"📋 Paste Polygon"** modal accepting GeoJSON and WKT from this proxy.
5. **Network Inspector & Exporter**:
   - Logs every API transaction, HTTP status code, latency (ms), request payload, and response.
   - **Export JSON**: One-click export of complete network logs (`fwt_network_traffic.json`) and route waypoints (`fwt_simulated_route.json`).

## 3. Database Tables to Know for Phase 08 & 09

### `mobile_event_logs` (The Core Input for Phase 08 & 09)
Raw location events sent by mobile phones via `POST /api/v1/mobile/events/batch` are stored here as an **immutable fact store**.

| Column | Type | Description |
|---|---|---|
| `event_id` | `UUID (PK)` | Unique event identifier generated by the mobile phone (idempotency key). |
| `employee_id` | `UUID (FK)` | Worker who produced the event. |
| `device_id` | `UUID (FK)` | Registered device used to capture the event. |
| `job_id` | `UUID (FK)` | Worksite where event occurred (optional; resolved by geofencing). |
| `accommodation_id` | `UUID (FK)` | Accommodation camp where event occurred (optional). |
| `event_type` | `VARCHAR(50)` | `ENTRY`, `PING`, `EXIT`, `LOCATION_DISABLED`, `LOCATION_ENABLED`. |
| `event_timestamp_utc` | `TIMESTAMPTZ` | Timestamp when the location was captured on the phone. |
| `latitude`, `longitude` | `NUMERIC(9,6)` | GPS coordinates. |
| `geom` | `Geometry(POINT, 4326)` | PostGIS spatial point for spatial SQL joins and containment queries. |
| `accuracy_meters` | `FLOAT` | GPS accuracy circle in meters. |
| `is_mock_location` | `BOOLEAN` | Anti-tamper flag for mock locations. |
| `server_received_at` | `TIMESTAMPTZ` | Wall-clock timestamp when backend received the batch. |
| `is_processed` | `BOOLEAN` | Processing state flag. **Defaults to `False`**. |
| `raw_payload` | `JSONB` | Full raw JSON event payload. |

#### Role in Phase 08 (Attendance & Timesheets):
- Phase 08 will implement the background attendance processor.
- It queries `mobile_event_logs` where `is_processed == False`.
- It groups events by `employee_id` and `work_date`, passes them to pure domain rules in `fw.rules.attendance`, matches against `day_plans` and scheduled shifts, computes actual work minutes, and updates `is_processed = True`.

#### Role in Phase 09 (Live Map & Operations Supervision):
- Phase 09's live map queries the latest `PING` / `ENTRY` / `EXIT` for each active worker within a sliding window (e.g. past 15-30 minutes).
- Visualizes worker presence pins, active worksite containment, and breadcrumb trails directly on the web dashboard.

### `base_roster_templates` & `base_roster_entries` (Base Planner Recurring Master)
- **Base Planner (`/base-planner`)** saves recurring master blueprint schedules here.
- `BaseRosterTemplate`: `id`, `job_item_id`, `allocation_mode` (`UNIFORM` or `DAY_OF_WEEK`), `start_date`, `end_date`, `is_active`.
- `BaseRosterEntry`: `id`, `template_id`, `employee_id`, `weekday_mask` (`MON`, `TUE`, ..., `ALL`, `W1_MON`), `assigned_hours`, `sequence`.
- **Phase 07 Fix**: `SyncService.build_snapshot` integrates these entries directly into mobile snapshots, so workers planned in the Base Planner automatically receive their shifts and worksite polygons without needing single-day operational records.

---

### `scheduled_work` (Operational Planner Overrides & Single-Day Shifts)
- **Operational Planner (`/operational-planner`)** saves daily overrides, covers, cancellations, and direct shifts here.
- `ScheduledWork`: `employee_id`, `work_date`, `worksite_id`, `job_item_id`, `status` (`ACTIVE` or `CANCELLED`), `source` (`OVERRIDE`, `DIRECT`, `PLANNED`).
- **Precedence Rule**: Operational records in `scheduled_work` override base blueprint records for that specific date.

---

### `sync_changes` (Delta Change Log)
- Per-worker change log table (`id BIGINT IDENTITY`, `employee_id`, `entity_type`, `entity_id`, `op`, `payload`, `priority`, `created_at`).
- Serves delta sync requests (`GET /mobile/sync/changes?cursor=N`).
- Domain event listeners in `fw.modules.sync.listeners` write entries here in the same database transaction.

---

### `registered_devices` (Device Bindings)
- Stores device hardware IDs, platform (`ANDROID`/`IOS`), push notification tokens, and sync cursors.
- Single-device binding enforces that a second device attempting to sign in is refused with `409 DEVICE_MISMATCH` until an administrator resets the binding.

## 4. Key Gotchas & Solutions Identified

1. **Base Planner vs. Operational Table Separation**:
   - *Problem*: Mobile sync was originally querying only `scheduled_work`. Workers allocated in the Base Planner appeared with `DAY_PLAN = FREE` and received 0 worksites.
   - *Fix*: `SyncService.build_snapshot` and sync listeners now resolve both `scheduled_work` (operational precedence) and `base_roster_templates` + `base_roster_entries` (recurring blueprint).
2. **MissingGreenlet on Spatial Geometry Access**:
   - *Problem*: Accessing spatial attributes like `worksite.boundary` or `acc.boundary` inside asynchronous event listeners raised `MissingGreenlet` errors because GeoAlchemy2 attempts lazy geometry translation.
   - *Fix*: Always query geometry explicitly using PostGIS functions: `select(Model, ST_AsGeoJSON(Model.boundary))`.
3. **Worksite Sync Scope Contract**:
   - Per `docs/09-mobile-sync-contract.md`, a worker's phone **only** syncs worksites where that worker has an active scheduled shift in the 30-day window. If a worksite polygon does not appear on the phone, verify that the worker is scheduled at that site.
4. **Coordinate Array Nesting (2D vs 3D)**:
   - GeoJSON coordinates can be 2D `[[lng, lat], ...]` or 3D `[[[lng, lat], ...]]`. All WKT / GeoJSON conversion helpers must inspect nesting depth before formatting coordinates to avoid `TypeError: undefined (reading 'toFixed')`.
